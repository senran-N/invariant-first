# 弃用、移除与退役

未加载时先读[共同规则](../../RULES.md)。保持当前主目标，不为加载专项方法重新分诊；执行 ACTION 后交付结果，不只汇报已读。专项技能从路由输出取实际路径。

## ACTION NOW

处理真实消费者与数据，移除已无责任的入口和资源。

用真实调用、已有数据和运行作业决定剩余责任，不凭文件名字像旧代码就删除。无消费者的实验代码直接清理；有消费者才需要过渡。不可逆操作单独遵守授权，不从路由标签推断许可。

**交付：** 已完成的弃用或退出增量，清楚的用户去向，以及范围内不再运行的旧路径。

## 区分没有依赖的删除与有人使用的退役

没有消费者、重要数据或支持承诺的实验代码，可直接删除并同步引用，不制造弃用周期。已有人依赖的能力按实际承诺退出；未知不能当作无人使用，也不因此无限保留所有实现。

## ACTION

1. 明确要结束的是内部模块、公开接口、部署服务还是整个项目；找相关调用、已有数据、运行作业和公开支持说明，只查受影响范围。
2. 有消费者时给出替代入口或明确无替代，并写清受影响版本、实际已批准的时间/条件及用户必须采取的动作。不能自己捏造支持终止日期。
3. 需要过渡时在正确边界给可行动的弃用提示，让新使用走新路径；不把新旧逻辑撒进每层。过渡期仍承担已承诺的必要维护，不将“已弃用”当作已停用。
4. 数据需要保留、导出或迁移时，按项目约定完成对应路径，再执行已授权的停止写入、停服务或删除。备份位置存在不等于可恢复；不可逆删除单独受授权约束。
5. 停用实际入口、作业、旧依赖及专用资源，按权限范围处理凭据与访问；共享资源不得连带删除。同步安装入口、当前文档和维护状态，历史记录保留历史身份。
6. 完成当前约定的切换/移除，并说明仍待履行的承诺和退出条件。若今天只授权发布弃用说明，就交付说明，不越权下线。

## DONE

目标范围不再依赖被移除能力，或本次批准的弃用增量已闭合；仍有责任则明确，而非留着看不见的双轨。不能把“仓库已归档”当作服务、资源和数据都已经处理。

**不要：** 删除先于数据和消费者处理；照搬大型平台的弃用年限；为未发布原型发明迁移机制；承诺未来自动关停而没有实际执行能力。

依据：R3（Kubernetes 弃用政策与 deprecation.go）、R1 的到期能力清理；服务与数据退出步骤为本 Skill 的适配。
