# 运行能力与故障恢复

未加载时先读[共同规则](../../RULES.md)。保持当前主目标，不为加载专项方法重新分诊；执行 ACTION 后交付结果，不只汇报已读。专项技能从路由输出取实际路径。

## ACTION NOW

确认用户侧影响，执行最直接的已授权恢复或运行改进。

不能用反复重启代替定位，也不能以紧急为由尝试不明命令。优先找当前目标环境和最近变更；每次动作后看用户侧实际结果。已恢复就停止扩大处置，再做授权范围内的根因工作。

**交付：** 实际可用的运行改进，或已恢复的服务及明确的剩余问题。操作范围受用户授权、当前事件负责人和工具权限约束。

## 正在影响用户：先恢复

1. 用当前信号确认影响、最近变更和受损路径；优先观察用户侧成功率、延迟或实际操作，不只看进程是否存活。只收集决定下一动作的必要信息。
2. 选择最直接、可逆、已授权的缓解动作：撤回相关变更、隔离故障能力、切换到已知可用路径或停止扩大影响。先保服务与数据，根因研究不要挡住明显有效的恢复。
3. 同一事件的变更需协调，不能和其他处置者互相覆盖；不因为紧急就绕过身份、权限、数据保护或发布授权。不能直接操作时，交付具体动作与判断条件，不假装执行。
4. 保留恢复所需的关键证据，查看动作后的实际结果。避免在真实数据上随机实验、重复非幂等写入、只重启不检查结果。
5. 恢复后移除已无必要的临时措施；仍需保留的降级写明影响与退出条件。根因修复仍属本次目标才转 fix；不在事故现场夹带全面架构升级。

## 日常运行改进：做能用的能力

围绕一个实际运行问题实现，例如错误可定位、超时可取消、资源受约束、备份可恢复、部署可诊断。利用已有日志、指标与平台，只添加能支持具体决策的信号；不要先堆监控面板和空告警。

备份任务交付恢复路径而不只有“备份成功”；演练在隔离目标上进行，不能覆盖生产数据。采集信号避免泄漏秘密或敏感内容，新增外部采集服务与费用需有授权。

## DONE

运行改进在目标路径可用，或受影响操作已恢复且剩余风险清楚；“进程重启了”不是服务已恢复。只做当前可执行的工作，不承诺会话结束后持续值守。重要操作及下一处置点留在已有运行说明，不造重复事件系统。

**不要：** 先写长篇事故分析再恢复；借止血掩盖数据不一致；用自动重试制造二次事故；把复盘文档任务误认成生产操作请求。
