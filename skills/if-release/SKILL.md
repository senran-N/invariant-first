# 打包与交付发布

未加载时先读[共同规则](../../RULES.md)。保持当前主目标，不为加载专项方法重新分诊；执行 ACTION 后交付结果，不只汇报已读。专项技能从路由输出取实际路径。

## ACTION NOW

用仓库真实流程构建分发产物，检查产物使用路径。

对照实际分发包检查所需文件、配置和依赖，避免开发工作区恰好补齐缺失。生成包、安装验证和公开发布分别报告。NEXT 中出现 release 不代表已有部署权限。

**交付：** 可识别、可使用的发布产物及必要操作说明；实际发布须在已有授权与工具权限内执行。

## ACTION

1. 明确交付对象、版本/修订、目标环境和发布渠道；沿仓库现有打包与部署流程。不因为写了部署文件就宣称已经上线。
2. 对第一次交付，跑通安装/启动/首次使用；对升级，加载 contracts，只处理受影响的支持环境、旧调用与数据。沿项目版本规则，不私自宣布稳定性承诺。
3. 构建实际要分发的包、镜像或静态产物。从产物而非工作目录检查关键路径，避免本机未打包文件、开发依赖与本地配置掩盖缺失。
4. 外部服务部署涉及状态时，从 state 取相应约束。明确配置与秘密来源、失败时停止扩大的条件，以及可行的回退或前向修复；代码回滚不等于数据回滚。
5. 用项目已有的发布方式交付。已有分批投放能力且确有风险就利用；不为一个小工具另造发布平台。最终发布行为、目标和副作用仍需符合用户授权。
6. 从实际分发内容与相对发布基线的差异写变化、安装/升级动作和已知问题；留意应交付但尚未纳入版本的文件。PR、提交与发布说明都不复制聊天过程或工具摘要，已撤回且未交付的尝试不列为产品特性。

## DONE

仅要求准备发布：产物与操作材料可用即交付。要求实际发布：报告真实发布位置、版本与已观察状态；凭据或能力缺失就明确哪些步骤没执行。发布后确有异常且处置已授权，转 operate；不无限监控，也不声称会在后台继续。

**不要：** 把绿 CI 等同于安装可用；以“做功能”为由默认获得推送、上架或生产部署授权；为赶发布绕过已有必要检查。

依据：R1（Django 5.2 发布指南）、S3–S4。回退、授权与按风险投放为工程归纳，不照搬 Django 的工具链与人员流程。
