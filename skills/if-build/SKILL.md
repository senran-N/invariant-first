# 预览与功能开发

未加载时先读[共同规则](../../RULES.md)。保持当前主目标，不为加载专项方法重新分诊；执行 ACTION 后交付结果，不只汇报已读。专项技能从路由输出取实际路径。

## ACTION NOW

先实现核心难点，再接通真实入口、处理与输出。

不要只实现最显眼的部分：按钮必须接到真实动作，后端必须接到入口，配置必须有实际读取者。多个目标按依赖顺序做完整增量，但用户要的整项任务未完成前不能用第一个 demo 宣告结束。新依赖和陌生 API 先核对项目版本；不要为赶进度用不存在的方法写出看似完整的代码。

**交付：** 约定功能的完整实现和真实用法，不是脚手架、接口空壳或工作计划。

## ACTION

1. 读相关入口、数据和调用方，选定主路径。先做最难、最不确定的核心，再贯通真实输入、处理、输出与必要副作用；实现约定的其余部分。
2. 新项目采用现成工具和小而清楚的数据结构。没有历史消费者就直接定接口，不建兼容分支；没有当前需求就不建多后端、插件平台和配置矩阵。
3. 已有项目沿领域边界加入能力，复用事实来源而非复制业务规则。遇到妨碍本次目标的坏局部设计，完成范围内替换；不保留一堆新旧包装来缩小 diff。
4. 各模块对完整责任负责。边界输入转成内部可信表示后直接使用，错误交给能恢复或准确报告的层；不让每个函数猜输入是否可靠。
5. 连上项目实际入口，补齐调用、配置、生成源及必要用法。维护生成文件时按仓库生成流程做，不能只修改下次就会被覆盖的产物。
6. 用当前环境跑核心真实用例，边做边修。服务不可用时可以在真实外部边界使用明确替身，但不能把替身结果说成端到端完成。

## 按现实改变力度

开发者预览砍范围，不砍本次完成度；安全保护仍跟暴露面走。已经有用户时，保持受影响的外部契约，内部直接简化；根据主入口触发相应专题。不要因为成熟仓库而给隔离实验增加历史包袱。

## DONE

用户能从实际入口使用约定功能，受影响的说明与调用已同步。没有发布请求就不自动转 release；不为假想规模继续扩建。外部条件阻塞时交付已完成部分并精确说明缺口，不能把核心 TODO 当已完成。

**不要：** 只做一个孤立 demo 就停止；把所有需求推迟到“下一阶段”；以优雅为由换全仓架构；以赶工为由引入第二个真相来源。

依据：S1–S2、S3、D1–D4。
