# 预览与功能开发

未加载时读取 [共同判断](../../RULES.md)。保持用户约定的目标和能力，只加载眼前需要的专项；不把实施自主权变成产品删减权。

## ACTION

1. 从目标、真实入口与核心数据选定能体现用户价值的完整路径，标明先验证的关键能力与后续仍需完成的部分。最早的有效增量要检验核心机制，不只证明框架能启动；必要基础先接通到可验证的程度，再回到核心。意向不清时按共同判断交流，不按实现便利替用户选重点。
2. 新项目用现成工具与清楚的小结构；没有真实旧消费者就直接定接口。已有项目沿承担规则的同类入口接入，复用责任而不只复制计算；替换坏局部设计时保留必须成立的语义。
3. 将输入、核心判断或处理、必要副作用和结果接通。补齐直接调用、配置及生成源，让用户从项目真实入口使用功能。用于接线的基线、替身或固定结果不能冒充要求的核心能力；外部环境不可用时，只在该边界明确使用替身并说明集成缺口。
4. 分别验证目标质量与必要底线，用目标场景、独立预期或适当基线检查结果；链路通过不代表判断有效。需要意向推断、策略选择等能力时，用会改变正确决策的条件对照检查该能力是否实际参与路径，再看效果是否符合约定；函数存在或返回合法并不足够。
5. 拿到关键反馈后，按尚未达标的用户结果选择下一步：解除阻断该结果的前提，再补缺失的能力或质量。基础已足够就回到核心，不继续用局部打磨代替目标进展；只调整受影响的安排。继续完成原授权的剩余工作并更新用法，交付前对照原要求与已同意的变更验收；受阻或待验证的部分保留为缺口。

## DONE

约定能力从真实入口可用，目标质量有对应证据，调用与说明一致。部分完成按部分完成交付，保留缺口；不以自己的缩减计划定义成功。完成用户约定范围后按请求衔接，不自动扩展产品路线图。
