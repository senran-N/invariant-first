# 文档 · 读完会用，换人会改

未加载时先读[共同规则](../../RULES.md)。普通开发中的几行文档同步不需要另开文档路线。

## ACTION

1. 读取要说明的实际代码、命令或已确认要求，先确定读者想完成什么；当前能力、计划和历史设计分开。
2. README 先回答用途、重要默认行为和最快开始。教程带人做成一件事；任务指南解决具体问题；参考写精确语义；架构说明写责任、边界和理由；迁移说明写旧用户必须改什么。
3. 示例写清必要前提、执行位置、完整动作与可辨认结果。不要用省略号隐藏关键步骤，不把预期输出写成本机实测。
4. 同一规则维护一个权威说明，其余链接过去。更新受影响的旧用法与入口，不并存两份互相矛盾的“最新版”；小项目不机械拆文件。
5. 按共同规则筛掉聊天残留。接口说明写使用契约，局部注释写有助维护的语义与理由，变更说明写最终差异和用户动作；没有本次对话仍有用的信息才留下。必要的非目标、历史故障和迁移事实不因精简而丢失。
6. 交付正文与导航，不只交目录或建议。需要重组较大说明或具体写法时，读[文档方法与示例](../../references/documentation.md)。

## DONE

读者不依赖聊天就能完成所述任务或定位正确修改处。实现疑点核对清楚，不能借写文档擅自更改公开行为。

依据：[来源 D1–D4](../../references/source-lessons.md#documentation)。借鉴 ripgrep、Django、Rust 与 rust-analyzer 的信息职责，不复制它们整个文档体系。
