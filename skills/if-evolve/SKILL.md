# 重构、迁移与转向

未加载时先读[共同规则](../../RULES.md)。保持当前主目标，不为加载专项方法重新分诊；执行 ACTION 后交付结果，不只汇报已读。专项技能从路由输出取实际路径。

## ACTION NOW

让新的完整路径承担工作，改完调用，结束无用双轨。

先找旧路径的真正入口、生成源和消费者，不能新建漂亮替代实现却没有切换调用。迁移增量里读写主次必须明确；失效路径、注释和文档一起收尾。不要把一次失败归咎于整个架构而从头重写。

**交付：** 更清楚或满足新方向的实现，完成范围内的调用切换与旧路径收尾。

## 先确定这次允许改变什么

移动、重命名和提取属于结构编辑：搬原内容，只更新必要的符号、路径与引用，不从记忆重新生成实现。重构保持约定行为；替换依赖保持所需语义；数据迁移保持数据含义；转向改变已授权的目标。把确需的语义重写与机械调整分清，别借搬文件重做业务逻辑。

## ACTION

1. 选一个具体结构问题或目标变化，读其主路径与消费者。看清表示承载的单位、精度、顺序、身份与时间基准，再判断是否冗余；不把整数金额、稳定排序或单调时钟分支仅因行数多而删掉。理由不明时只查相关定义、用例或局部历史，不先审计全仓。
2. 在该边界直接实现新的完整路径。新核心风险高时先做能决定取舍的最小验证；普通局部重构无需另建试验项目。
3. 没有历史依赖就直接切换并删除失效实现。有真实消费者或数据迁移时加载 contracts；对存储、并发和外部写入再取 state 相应小节。
4. 迁移期间明确哪边读、哪边写、谁是真相、何时切换。优先简单可执行的路径；确需双读双写时处理同步与部分失败，不能把双轨当默认保险。
5. 改完范围内的调用、配置、生成源、测试预期和文档；只在承诺仍需履行处保留有明确责任的兼容入口。旧依赖已结束就清理，不为少动文件留空包装。
6. 保持行为的修改用现有用例或针对性比较约束；有意改变行为的修改把新规则写明。验证服务于切换，不用漂亮的新目录树作为收益证明。

## DONE

新路径在目标范围承担真实工作，旧路径已移除或其剩余责任与退出条件清楚。跨版本长期迁移允许分次交付，但本次迁移增量必须闭合，不能把一半调用悬空。

方向尚未决定且用户只要评估时走 frame；已批准转向就完成当前范围，不再次把决策推给用户。已经终止的能力如需消费者退出则由 retire 收尾，不无限双轨。

**不要：** 把“兼容”当不敢改内部的借口；把代码回滚等同于数据回滚；只改命名与层次却让事实更分散；混入不相关的清理。

依据：S2–S5、S6、D4；完成切换、迁移顺序与退役衔接为本 Skill 的工程归纳。
