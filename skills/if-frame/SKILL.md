# 定向、架构与接手

未加载时读取 [共同判断](../../RULES.md)。先确定做对什么，再确定怎样做；方案应能指导后续实现。

## ACTION

1. 辨认使用者的核心目标、必需能力与成功标准。已有明确答案就沿用；会改变方向的意向分歧，在对话中用具体场景与推荐选项核对，按回答调整决定。仓库事实自己查，普通可逆选择自主处理。
2. 找到产生核心价值的机制：输入与可用信息怎样影响判断、动作和结果，用什么证据区分好坏。先研究决定成败的未知；必要基础服务主目标，不能用接线或稳定运行代替核心能力。体验或可行性需要证据时，用样例、草图或授权内的小实验帮助取舍。
3. 从真实入口追到数据、责任与直接消费者，复用适用机制。选择满足目标、保持真实契约且理解成本合理的边界；局部取舍足以决定就行动，不为比较另造两套实现。
4. 为每项必需能力确定责任、主路径与验证方式，最难的部分也要落实机制。按价值、依赖与风险安排实施顺序，区分试验、首个增量和完整交付；范围与标准的变化按共同判断协商。新事实否定核心假设时，及时给出影响与可行选项。
5. 成稿直接呈现选定方案及其理由，按读者实现所需的关系展开；具体未决事项放在受其影响的位置。接手任务给真实代码地图。修订回应留在对话中，正文按共同判断编辑，不逐项复述检查过程。

## DONE

方案能指导核心能力的实现与验收，接手判断能指向修改位置；真实未决项与部分成果清楚。只要求设计或解释时不擅自改代码；实施已在授权内就继续 build。
