# 定向、架构与接手

未加载时读取 [共同判断](../../RULES.md)。先确定做对什么，再确定怎样做；方案应能指导后续实现。

## ACTION

1. 辨认使用者的核心目标、必需能力与成功标准。已有明确答案就沿用；会改变方向的意向分歧，在对话中用具体场景与推荐选项核对，按回答调整决定。仓库事实自己查，普通可逆选择自主处理。
2. 沿代表性场景走通核心机制，交代输入如何转换、关键决定凭什么作出、结果由谁产生。需要估值、排序或搜索时，落实候选来源、判据依据及影响结果的约束与停止条件；复用已有机制就指向其契约。关键一步仍需猜规则，就补该决定或明确需要的证据，不用算法名代替它。体验或可行性不明时，用样例、草图或授权内的小实验帮助取舍。
3. 从真实入口追到数据、责任与直接消费者，复用适用机制。选择满足目标、保持真实契约且理解成本合理的边界；局部取舍足以决定就行动，不为比较另造两套实现。
4. 为其余必需能力确定责任与验证方式，按价值、依赖与风险安排实施顺序。细节展开到下一步不必重猜核心决定即可；普通选择沿用项目约定，未定参数保留依据或校准办法，不编数值凑齐规格。必要基础服务主目标，试验与首个增量保留总体承诺；范围变化或核心假设失效时及时协商。
5. 成稿直接呈现选定方案及其理由，按读者实现所需的关系展开；具体未决事项放在受其影响的位置。接手任务给真实代码地图。修订回应留在对话中，正文按共同判断编辑，不逐项复述检查过程。

## DONE

下一位能沿关键场景解释一次决定，并据此实现与验收；接手判断能指向修改位置，核心未决事项有明确落点。已有机制足够就复用，不为简单任务补一套演练文档。只要求设计或解释时不擅自改代码；实施已在授权内就继续 build。
