# 架构判断

未加载时读取 [共同判断](../../RULES.md)。为当前 PRIMARY 决定复杂性与责任放在哪里，保持其操作范围。

## ACTION

1. 沿当前主路径识别事实来源、状态修改者、消费者与外部效果；先让数据关系清楚，再安排模块。
2. 将必须一起成立的事实收在能建立保证的表示或边界。用语义而非故事名称判断冗余；派生状态确有价值就明确其更新与失效责任。
3. 按共同变化的知识划界。接口承担完整操作，让调用者无需知道内部步骤；依赖方向与生命周期看得见。
4. 比较直接实现与抽象后的理解成本。能消掉特殊情况的表示优先，能隔离真实变化的边界保留；形式相似但语义不同的逻辑不强行统一。优雅服务于局部可理解。
5. 在授权范围落到实现，或交付目标要求的设计/审查判断。同步受影响的短地图，就地记录未来仍需知道的边界与原因。

## DONE

当前变化有明确落点，理解一个职责只需读它与直接协作者，随后继续 PRIMARY。判断依据见 [成熟实现](../../references/source-lessons.md) 与 [机制归纳](../../references/ai-coding-pain-points.md)。
