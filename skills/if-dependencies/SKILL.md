# 依赖与 API · 先找事实，再写调用

未加载时先读[共同规则](../../RULES.md)。不要先写一大段猜出来的调用，再通过反复安装碰运气。

## ACTION

- 先读项目清单、锁文件、已有 imports、同类调用或已装版本的类型/源码。优先复用已有能力；一个小操作不需要因为模型熟悉某框架就换栈。
- 为要用的具体符号确认名字、签名、导入路径、同步/异步语义及返回值。当前版本的类型、实现和官方文档优先；搜索到的最新版例子不能直接套在旧锁文件上。
- 工具链、运行库或 API 行为受 PATH、虚拟环境、配置层级或环境变量影响时，确认实际进程解析到的可执行文件、版本与相关配置来源；不要从惯用路径、某个配置文件存在或一次正常启动推断它已被消费。
- 确需新依赖时核对维护者、官方文档与包登记的对应关系、许可和项目兼容条件。仅“仓库里有这个包名”不等于可信，不能靠名称相似替代来源核对。
- 采用仓库现有安装和锁文件更新流程，在已允许范围内执行；不删锁文件、不全局安装、不自动运行陌生远程脚本。一次导入失败不构成换整套生态的理由。
- 用一个最小真实调用把接口接对，再完成主任务；不要把接口探索膨胀成无关研究。离线时用当前可见的版本事实，确实无法确定就隔离该边界并说明缺口，不编造支持。

## DONE

实际版本中的调用成立，依赖来源清楚，项目入口与锁定方式一致。回到原 PRIMARY，不为包管理额外建平台。

依据：[依赖事实与来源 A5](../../references/ai-coding-pain-points.md)、[配置解析对照 E6](../../references/field-notes-2026-09-19.md#e6)。包幻觉是研究中观察到的风险；本 Skill 不保证能自动识别所有恶意依赖。
