# 交互实现 · 用户能做，不只是能看

未加载时先读[共同规则](../../RULES.md)。沿用现有设计语言、语义和组件，不为显示创造一套新平台。PRIMARY 是审查或文档时，仅用以下方法判断或说明交互，不把专项的实现动作视为修改产品的授权。

## ACTION

先选用户要完成的一条实际动作：输入什么，触发什么，结果在哪里，失败时怎样继续。沿这条路径接通组件事件、真实状态与必要后端，不把点击变成没有效果的提示框。

状态只保留必要的一份权威事实。异步响应顺序、切换页面后的过期结果和重复提交由明确责任处理，不让展示层复制业务规则。原生控件和框架已有无障碍机制优先，保持标签、键盘可达性和反馈可辨认。

只补当前路径实际存在的等待、空结果、失败与恢复状态，不枚举所有假想场景。真实需求是拖拽、编辑、下载或取消，就把行为做出来；替身只放在外部不可用边界，并明确标识。

有交互工具就从真实入口操作；没有就做可执行的组件与接口检查，说明未亲自操作的范围。类型检查通过不是交互完成，截图漂亮也不是按钮可用。

## DONE

当前用户动作有真实结果和反馈，界面没有用静态演示冒充核心功能。回原 PRIMARY 补齐约定其余内容与文档。

依据：[完整交互依据 A1、A2](../../references/ai-coding-pain-points.md)。不要求每个界面改动搭建浏览器平台，也不因缺浏览器停止可完成的代码工作。
