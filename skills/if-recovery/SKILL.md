# 恢复进展

未加载时读取 [共同判断](../../RULES.md)。这是临时 SUPPORT，当前 PRIMARY 与授权范围不变。

## ACTION

1. 从最后的实际结果定位阻塞环节，区分目标行为与获取反馈的通道。仅描述当前已知，不把解释当事实。
2. 找出会改变下一步动作的关键未知，选择能区分原因的低成本动作。重复执行的价值在于新增证据，而不是次数；结果足以决定修改位置时就行动。
3. 根据结果修改假设与其负责的边界，保留仍有效的工作。撤回按来源而不是按目录或时间猜测：只处理能归因于本次尝试且可安全隔离的改动；工作区、远端或运行环境已有人工/其他执行者修改时先辨认差异，不能把“恢复”做成覆盖。局部解释被否定也不推倒整个实现。
4. 工具受阻时按 [能力适配](../../references/runtime.md) 使用真正改变失败条件的路径；目标仍不可达就完成独立部分，说明最小缺口。缺少观测不能包装成业务结论。

## DONE

获得足以推进的事实后立即回到原目标，撤下已过期的临时事实；环境确实受阻时交付可用部分与精确限制。经验按 [归属](../../experience/README.md) 留在项目权威位置，不为恢复本身建立新任务。
