# 恢复进展

未加载时读取 [共同判断](../../RULES.md)。这是临时 SUPPORT，当前 PRIMARY 与授权范围不变。

## ACTION

1. 从最后结果确认阻塞的是执行还是观察。按原任务句柄、状态记录或产物判断当前进展；日志安静不等于停滞，持续输出也不等于目标推进。阈值服从实际操作与宿主能力，不从一次等待推断整个任务失败。
2. 区分等待原操作、取回结果与重新执行。选能改变决定的最小观察；确有暂时故障且可安全重复时，沿原操作在已有预算内重试。诊断循环须带来新证据或改变失败条件，足以定位就行动，不重跑整个流程来“查看结果”。
3. 根据结果修改假设与其负责的边界，保留仍有效的工作。撤回按来源而不是按目录或时间猜测：只处理能归因于本次尝试且可安全隔离的改动；工作区、远端或运行环境已有人工/其他执行者修改时先辨认差异，不能把“恢复”做成覆盖。局部解释被否定也不推倒整个实现。
4. 工具受阻时按 [能力适配](../../references/runtime.md) 使用真正改变失败条件的路径；替换工具前保留原操作的已知效果与未决状态。目标仍不可达就完成独立部分，说明最小缺口，不把缺少观测包装成业务结论。

## DONE

获得足以推进的事实后立即回到原目标，撤下已过期的临时事实；环境确实受阻时交付可用部分与精确限制。经验按 [归属](../../experience/README.md) 留在项目权威位置，不为恢复本身建立新任务。
