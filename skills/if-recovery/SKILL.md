# 失速恢复 · 换一个能区分原因的动作

未加载时先读[共同规则](../../RULES.md)。这是临时 SUPPORT；当前 PRIMARY 和用户目标不变。

## ACTION

1. 停止重复没有改变条件的命令或补丁。保留已知有效的工作，概括最后的真实错误和刚被排除的假设；不用重新复述全项目。
2. 区分环境、目标选择和实现：是否运行了正确目录、版本、文件或构建产物？无法 import 和业务断言失败不是同一个问题。
3. 换一种能区分原因的观测：缩小输入，直接调用边界，读数据生产处，检查已装版本符号，或捕获一次关键状态转移。不要把“再试一次”换个说法。
4. 撤回自己已证实无效且可安全隔离的局部改动，选择得到新证据支持的修复。禁止用全仓 reset、删除用户修改、弱化测试或关闭功能掩盖失败。
5. 若阻塞来自工具，按[能力适配](../../references/runtime.md)换可用路径。真实环境仍不可用时完成不受阻部分并指出最小缺口；不无限重试，也不假装结果已验证。

替代路径必须改变失败条件或增加信息；同一 DNS、权限或服务故障下只换 URL、参数拼法或继续重装不是新方法。可用路径仍被同一障碍阻断时，完成独立部分并交付精确缺口，不用无限重试维持忙碌。障碍解除就退出 recovery，不保留过期的 stalled/environment_blocked 事实。

## DONE

出现能继续实现的新事实或完成可交付的阻塞说明，就返回原 PRIMARY。不要把恢复流程变成长期计划和新的报告工程。

修复作用域跟根因走，不跟焦虑走。经验可复用时按[回流规则](../../experience/README.md)留下条件和依据，不能把一次猜测记成永远有效的先例。
