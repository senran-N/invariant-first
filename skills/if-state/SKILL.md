# 专题 · 在真实边界承担责任

只读与本次改动相关的小节；有几个真实风险就处理几个，不因模板追加整套审计。校验过的保证跨等待、锁释放或外部修改可能失效，不能当成永远可信。

## ACTION

先读或复用已加载的[共同规则](../../RULES.md)。定位本次风险的入口、状态所有者和成功边界，直接修正对应责任，再回到原 PRIMARY；不对未触及的系统追加一套安全审计。

## 不可信输入、权限与秘密

在接受外部输入并建立内部表示的边界验证格式、范围与资源成本；在执行受保护操作的位置检查相应授权，不靠 UI 隐藏或类型断言代替。现有框架已提供安全机制就正确使用，不自造认证或加密。

不以“开发者预览”为由暴露真实秘密、用户数据或无限资源；日志只保留排障所需信息。合法缺失可以用约定默认值，非法必需值不能悄悄变成成功。独立威胁的防护保留，同一仍有效的保证不层层重复。

## 持久化与外部效果

明确动作何时被视为成功，失败前可能留下什么，谁清理或恢复；使用已有事务、资源生命周期和原子写入机制。测试、预览和迁移工具若具有删除、覆盖、发信、扣费等真实副作用，先确认它们指向隔离且可丢弃的资源；“只是测试”不能把真实用户数据变成测试夹具。如果 watcher、热重载、并发读者或外部系统会观察修改过程，就把可见的中间状态也算进契约：优先在隔离位置准备完整结果后一次发布，而不是先暴露空文件、半配置或半迁移状态。成功响应不能早于契约要求的实际保证，也不必为不相关操作创造分布式事务。

区分跟进已有操作与重新提交。有可靠句柄就续取进度或结果；明确未执行且故障可恢复，或接收方允许安全重放时，沿原意图重试。其余未决效果先核对权威状态；查无记录还受可见性与保留期约束，不能直接当作未执行。无法判定就保留未决并推进独立部分。恢复或补偿不假设副作用天然可撤销；迁移时区分重试、恢复、代码回退和前向修复，验证关键失败后状态。

## 并发、取消与重试

给共享状态一个清楚的拥有者或同步边界，把需要一起成立的条件与更新放在同一原子操作中。先检查后执行不能自动防止竞争；释放锁、await 或接受外部变更后重新判断相关保证。后台或并行工作可能在更晚时刻完成时，不把“超时、切到下一步、发出取消”当成它已经停止；让结果先落到隔离位置，或在发布前用现有锁、版本号、前置条件等确认它仍对应当前目标，避免旧工作覆盖新状态。

可重算的状态计算不做不可重复的外部动作。需要去重时，以一次业务意图保持操作标识、参数与授权范围，在接收方承诺的范围和有效期内复用；相同参数的独立意图仍是不同操作。客户端加键或记日志本身不构成接收方的去重保证。

业务重试只针对可恢复条件。先核对 SDK、队列等已有重试，由掌握失败语义的层负责，约束累计尝试与总截止，不逐层重置预算。按协议处理取消、退避与去重，不给既有同步算法凭空加网络重试策略。并发数量和队列受实际资源约束；取消时处理持有的资源与部分结果，不以无穷队列掩盖过载。

## 错误归属

能恢复、翻译语义、提供必要上下文或释放资源的层才接住失败；保留原因与部分效果语义，不重复打印同一错误，不用 catch-all 返回伪成功。断言用于内部诊断，不能承担发布环境必需的副作用、权限或输入检查。
