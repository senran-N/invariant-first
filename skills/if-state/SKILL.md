# 专题 · 在真实边界承担责任

只读与本次改动相关的小节；有几个真实风险就处理几个，不因模板追加整套审计。校验过的保证跨等待、锁释放或外部修改可能失效，不能当成永远可信。

## ACTION

先读或复用已加载的[共同规则](../../RULES.md)。定位本次风险的入口、状态所有者和成功边界，直接修正对应责任，再回到原 PRIMARY；不对未触及的系统追加一套安全审计。

## 不可信输入、权限与秘密

在接受外部输入并建立内部表示的边界验证格式、范围与资源成本；在执行受保护操作的位置检查相应授权，不靠 UI 隐藏或类型断言代替。现有框架已提供安全机制就正确使用，不自造认证或加密。

不以“开发者预览”为由暴露真实秘密、用户数据或无限资源；日志只保留排障所需信息。合法缺失可以用约定默认值，非法必需值不能悄悄变成成功。独立威胁的防护保留，同一仍有效的保证不层层重复。

## 持久化与外部效果

明确动作何时被视为成功，失败前可能留下什么，谁清理或恢复；使用已有事务、资源生命周期和原子写入机制。成功响应不能早于契约要求的实际保证，也不必为不相关操作创造分布式事务。

外部写入超时可能是“结果未知”，不是“没有发生”。恢复或补偿不得假设它天然可撤销；涉及重要数据迁移时区分重试、恢复、代码回退和前向修复。核对被改变的关键失败后状态，而非只跑成功路径。

## 并发、取消与重试

给共享状态一个清楚的拥有者或同步边界，把需要一起成立的条件与更新放在同一原子操作中。先检查后执行不能自动防止竞争；释放锁、await 或接受外部变更后重新判断相关保证。

可重复执行的状态计算不做不可重复的外部动作。业务重试只用于明确可恢复条件，有截止/次数、取消、退避及去重或幂等语义；各项按实际协议确定，不给既有同步算法凭空加超时。无法保证幂等的动作不能盲目重放。

并发数量和队列受实际资源约束。取消时处理正在持有的资源与部分结果，不留下幽灵任务；不能用无穷队列掩盖过载。

## 错误归属

能恢复、翻译语义、提供必要上下文或释放资源的层才接住失败；保留原因与部分效果语义，不重复打印同一错误，不用 catch-all 返回伪成功。断言用于内部诊断，不能承担发布环境必需的副作用、权限或输入检查。

依据：S4（SQLite 状态与失败）、S5（Clojure 重算与副作用）；具体业务重试、取消与授权安排为本 Skill 的工程归纳。
