# 跨会话 · 重新获得事实，不重新做整个项目

未加载时先读[共同规则](../../RULES.md)。保留原 PRIMARY；只有用户主要要接手分析时才以 frame 为主。

接续是继续开发的准备动作，不是独立交付阶段；需要它时应在领域修改之前恢复事实，而不是被兼容或状态专项挤到最后。恢复完成即返回原目标，小改不因上一轮对话存在就自动创建交接任务。

## 恢复时 ACTION

读取现有任务/交接位置和相关仓库入口，核对当前文件与可用差异。先从短入口找到权威位置，不把整个说明库重新塞进上下文。笔记是索引，不是比代码更高的真相；过期路径、旧假设和历史成功不能直接当成今天的状态。

恢复用户当前目标与硬约束、最后完成的增量、仍未完成的部分和下一动作。已有运行命令与已排除原因直接复用；不重新全仓探索，不重复询问已经记录的选择。

多个执行者同时存在时确认正在修改的区域，避免把别人的新改动当异常清理。没有协作工具就串行完成，不假定另一个 Agent 会替自己收尾。

## 暂停时 ACTION

只在确需接续时更新项目已有位置；小改不造文件。内容足够回答：

```text
目标与边界：当前要完成什么，什么不能改变？
当前状态：哪些路径已经实现，哪些仍是未完成或替身？
关键决定：为什么选这条路径，对应代码在哪里？
实际反馈：运行了什么，最后失败或未运行什么？
下一动作：从哪个文件/符号开始，做哪件具体事？
```

稳定知识进入测试、配置、代码或正式文档，临时状态只指向它们。不要保存私有思维过程、秘密、整段工具输出或一份复制的需求库；不自动提交或修改全局 Skill。

## DONE

下一位可以从真实文件接着做，不必重构你的聊天意图。一个功能完成不是整个项目完成，交接也不是故意提前结束可继续执行的任务。

依据：[痛点 P3 与来源 A1、A3](../../references/ai-coding-pain-points.md)。它是可移植的接续方法，不要求特定 memory 工具、自动压缩机制或后台 Agent。
