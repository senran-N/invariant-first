# 缺陷与根因修复

未加载时先读[共同规则](../../RULES.md)。保持当前主目标，不为加载专项方法重新分诊；执行 ACTION 后交付结果，不只汇报已读。专项技能从路由输出取实际路径。

## ACTION NOW

追到最早失真的事实或状态转移，完成最小完整修复。

修复前区分：事实在生产时就错，传输/序列化时失真，还是消费者解释错。先找负有该规则责任的层，不为每个消费者补丁。几次相似修改仍同样失败时保留新信息、撤回自己无效的局部变更并启用 recovery，不继续堆 guard。

**交付：** 目标错误被修复、相关调用一致、以后可再次识别这个问题。

## ACTION

1. 从实际错误、最短输入和相关调用路径定位；区分环境、配置与实现问题。已有可靠复现就使用，不为流程重建一套。
2. 找到最早失真的事实、错误状态转移或责任缺口。先问数据表示和所有权能否直接消掉错误，再考虑加 guard；缺失的必要边界校验就补在边界。
3. 选择最小完整修复。需要改几处调用就一起改，需要替换局部结构就替换；不要用默认值、吞错、无条件重试或每层判空保住坏路径。
4. 回归到用户预期及真实契约，不盲目维护一个确有缺陷或不安全的行为。外部语义确需改变时按 contracts 给出已授权的迁移或影响处理。
5. 通过最近的真实入口重跑目标用例：替身放在必要的外部效果边界，保留被修逻辑，检查用户可见结果或状态而不只检查 mock 被调用。竞态用可控交错；持久化看失败后状态。保留有效复现并运行相关检查；无法重演旧版就直说，不让红绿仪式阻塞明确修复。
6. 漏洞修补沿项目安全流程处理，核查修复版本和相关支持分支；不把敏感复现材料不加区分地公开。依赖升级要确认实际消除问题，不只改版本字符串。
7. 按共同规则移除无效修法及其文字残留；保留能识别真实缺陷的回归用例和当前实现理由。

## DONE

目标问题不再出现，受影响主路径与说明一致。根因仍未知但临时缓解已有效时明确标为缓解，不冒充根治。若正在扩大线上损失且请求处置，先由 operate 恢复，再回到这里。

**不要：** 把测试基础设施失败当作目标 bug；弱化断言制造通过；修一处问题顺手全仓格式化；为了少改几行保留重复真相。

依据：S4、S6；轻量复现、生命周期责任及禁止测试替代实现是本 Skill 的操作归纳。
