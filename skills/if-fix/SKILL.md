# 缺陷与根因修复

未加载时读取 [共同判断](../../RULES.md)。目标是纠正已观察到的错误，结构调整只是手段。

## ACTION

1. 沿实际错误、最小相关输入和直接调用定位，复用已有可靠复现。先判断反馈是否触达目标，再区分已观察现象与根因假设；多种解释影响修法时取得一次能区分它们的观测，原因明确时直接修改。
2. 找到最早违背目标语义的表示、转换或状态迁移。缺失的边界保证在边界补，错误规则在拥有它的位置改；修复应改变产生现象的条件，而不是为每个猜测分别添加机制。
3. 完成相关调用与状态处理。需要替换局部结构就替换；外部契约确需改变时加载 contracts，正在扩大用户侧损失且请求处置时，由 operate 先恢复使用。
4. 让反馈经过被修逻辑，检查实际结果和相关旧行为。复用能暴露缺陷的输入；对检查敏感性有疑问时，在隔离副本中用已知坏结果或局部对照确认，而不改真实资源来制造故障。状态问题观察失败后的状态，并发问题控制交错。保留有效复现或适当回归测试，不为重建历史阻塞明确修复。
5. 涉及漏洞时沿项目安全流程核对修复和支持范围，按敏感性处理复现材料。反馈无新信息则用 recovery 改变观测，再继续当前目标。

## DONE

根因及受影响路径已修正，相关用法一致。仅恢复可用而根因未解时明确为缓解；未执行的检查如实说明。按共同判断清理无效尝试，保留真实回归依据。
