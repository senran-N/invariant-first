# 文档写法：读完能行动，不靠猜

作为 document 主路线，在文档是主要交付物或需要重组较大说明时读取。交付可以直接使用的正文与导航，而非写作建议；沿用仓库语言、术语与格式。普通开发中的小幅同步由核心规则直接完成，不必专门加载。以下是信息职责，不是每个项目都要新建的文件清单。

## 先决定读者在做什么

| 读者问题 | 写什么 | 不要混入什么 |
| --- | --- | --- |
| 这是什么，适合我吗，怎样开始？ | README：用途、关键默认行为、最短用法、下一步链接 | 完整 API 表、全部设计历史、空泛宣传 |
| 第一次怎么做出结果？ | 教程：选一条成功路径，逐步给文件、操作和结果，再解释必要概念 | 一开始罗列所有实现方案与参数 |
| 已会基础，怎么完成这个任务？ | 任务指南：前提、动作、结果、相关限制 | 重讲整个入门教程或内部实现 |
| 这个接口究竟如何工作？ | 参考：精确语义、默认值、单位、顺序、错误、副作用等相关信息 | 大篇概念课或从签名机械复制的废话 |
| 我要加功能，改哪里，哪些边界不能乱动？ | 架构说明：主路径、核心责任、真实代码入口、约束及理由 | 全量文件树、把所有实现细节复制一份 |
| 升级后我要改什么？ | 迁移说明：受影响版本与用户、旧写法到新写法、必要数据步骤 | 只有提交哈希或“改进了架构” |

先给读者当前需要的答案，再链接下一层。小项目可在 README 内完成这些职责；内容妨碍查找时再拆分。重要风险放在相关动作之前，不把每段都变成免责声明。

## 写法落到句子里

用任务和领域词作标题，例如“排除生成目录”，不要只写“高级能力”。一段解释一个判断，一段代码做一件事；术语与代码一致。需要表述实现理由时，说明被避免的具体问题，不用“最佳实践”替代理由。

默认值、配置项和行为细节尽量指向现有权威定义。允许为了读者理解重复少量上下文，不维护互相漂移的参数手册。能从签名看出的类型不必赘述，签名看不出的行为必须讲清。

命令说明执行位置和前提；可直接复制的代码块不混入 shell 提示符或输出。占位参数明确标识并说明如何获得，不能包含真实凭据。演示副作用要直说，不把演示设置推荐成生产配置。

## 示例：从空泛介绍变为可以执行的说明

不写：

> 提供强大、灵活的搜索能力。配置完成后运行即可。

写成下面这样；这是原创写法示例，不是摘抄上游 README：

### 在两行文本中只匹配 ready

前提：已安装 ripgrep（命令名 `rg`），使用 POSIX shell。任意目录运行：

```sh
printf 'ready\nfailed\n' | rg --no-config --color never '^ready$'
```

输出：

```text
ready
```

该例搜索标准输入，不读写磁盘文件；`^` 与 `$` 限定整行匹配，`failed` 不匹配。选项排除个人配置与颜色对演示的影响。编写者应实际运行适合当前项目的示例，不能把预期输出称作本机实测。

## 示例：架构说明留下理由，而不是罗列目录

下面是虚构搜索项目的写法示例，不代表当前仓库已有这些文件。实际使用时必须换成读过的真实路径，并添加链接。

> `cli.py` 解析参数，交给 `search.py` 搜索，再由 `output.py` 格式化结果。
> 搜索层只接收明确的根目录，不读取进程当前目录；这让 CLI 和编辑器可以复用它而不互相影响。
> 新增过滤条件改搜索层；新增 JSON 输出改输出层，不复制扫描逻辑。

这段说明同时给出主路径、责任、刻意排除的依赖和扩展位置。局部实现已经表达清楚的内容不再展开；必要的取舍理由保留在对应边界附近。

## 注释和变更说明各司其职

接口说明让调用者知道怎样使用；局部注释解释代码未能直接表达的语义和理由；PR、提交与发布说明解释最终差异及其影响。先看当前文件和实际差异，再写说明，不把聊天摘要贴进仓库。

用“没有这次对话，维护者还需要这句话吗？”筛选文字。下面是虚构例子：

- `amount_cents` 附近说明“账单金额使用整数分，避免结算舍入误差”，有真实语义价值；名称已经足够表达单位时无需重复。
- 功能里已移除自行添加的缓存，就直接说明功能；“应用户要求，这里没有 Redis”只是在复述纠正。
- 已发布接口的撤销影响旧用户，仍应写清受影响版本与迁移动作，不能作为聊天残影删除。

保留能指导未来使用或修改的非目标与取舍，不自动列出未实现能力清单；提交说明也不把开发中未交付的尝试当作用户得到的变化。依据与适用限制见 [E5](field-notes-2026-09-19.md#e5)。

## 随行为一起维护

修改实际用法就同步修改对应文档，不另写一份与旧说明并存的“最新版”。新文档从现有入口能找到，旧链接按仓库约定修正或重定向。历史设计和发布记录保留历史身份，不能让其冒充当前操作指南。

纯文档任务直接交付正文；发现实现疑点先核对，不借写文档擅自改公开行为。预览阶段把现有用法和限制写明，有用户后补齐真实契约，迁移时把旧用户必须执行的变化写清；不提前堆出完整文档平台。

依据见[来源 D1–D4](source-lessons.md#documentation)。借鉴的是组织与表达方式，不是把上游旧命令、路径和测试体系复制给当前项目。
