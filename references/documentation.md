# 文档写法：读完能行动，不靠猜

文档是主要交付物或需重组较大说明时读取。沿用项目语言、术语与格式，直接写可使用的正文；普通开发中的小幅同步按共同判断完成。

## 按读者任务组织

| 读者问题 | 内容 |
| --- | --- |
| 这是什么，怎样开始？ | README：用途、关键默认行为、最短用法与下一步链接 |
| 第一次怎么做出结果？ | 教程：一条成功路径上的前提、操作与结果 |
| 已会基础，怎么完成这个任务？ | 任务指南：所需前提、动作与相关限制 |
| 接口究竟怎样工作？ | 参考：默认值、单位、顺序、错误、副作用及精确语义 |
| 该怎样实现或修改？ | 设计与架构：机制、数据流、责任、关键取舍与验证；已有代码提供真实入口 |
| 升级后我要改什么？ | 迁移说明：受影响版本与使用者、替代写法和必要数据步骤 |

先回答当前问题，再链接下一层。小项目可在 README 内承担这些职责，内容妨碍查找时再拆分。篇幅取决于任务信息量：完整设计保留必要机制，局部修改只改受影响内容。

## 把讨论转成成稿

按已确定的事实重写对应段落，而不是在旧文末追加对话答复。方案写采用什么机制及理由，范围写覆盖哪些能力，验收写怎样判断完成。对纠正的回应与正文分开；只有读者需要理解的历史才进入记录。比较方案时保留真正决定取舍的差异。

用标题、状态标识或语态说明文档处于设计、实施还是历史阶段。具体未知与未验证结论就近标明，影响操作安全的风险放在动作之前。删去重复状态声明时，仍核对相关能力、条件和证据是否保全；已发布迁移、真实不支持项和有理由的负面约束不作为聊天痕迹删除。

例如，已经决定保留两路检索后，设计正文可以直接写：

> 查询层合并词法与语义候选，排序层按相关性重排。验收覆盖语义相近但字面不重合的查询。

这里保留机制和可区分能力的判据。无需在正文复述此前删掉哪路、承诺以后不再删减。若读者要的就是修订说明，则应说明两路保留这一变化及其影响。

## 句子与示例

用任务或领域词作标题。一段提供一个判断及必要依据，术语与代码一致。接口写签名表达不了的语义；局部注释保留未来修改需要的理由。默认值与配置细节指向权威定义，少量必要上下文可重复，避免维护两份参数手册。

命令写清前提与执行位置，可复制代码块与输出分开。占位参数说明如何取得，不放真实凭据；演示的副作用要明确。编写者实际执行适合项目的示例，区分预期输出与观测结果。

### 只匹配整行 ready

前提：已安装 ripgrep（`rg`），使用 POSIX shell。任意目录运行：

```sh
printf 'ready\nfailed\n' | rg --no-config --color never '^ready$'
```

输出：

```text
ready
```

该写法示例搜索标准输入，不读写磁盘文件；选项排除个人配置与颜色的影响，`^` 和 `$` 限定整行匹配。

### 架构说明给出修改位置

写法示例；路径需替换为项目实际入口并添加链接：

> `cli.py` 解析参数，交给 `search.py` 搜索，再由 `output.py` 格式化结果。
> 搜索层只接收明确的根目录，不读取进程当前目录，使 CLI 和编辑器可以独立复用。
> 新增过滤条件改搜索层；新增 JSON 输出改输出层。

“搜索层不读取当前目录”保留了隔离理由，和复述一次被否决的实现不同。更多取舍仅在会影响后续使用或修改时展开。

## 随行为维护

用法变化就更新权威正文和入口，旧链接按项目约定修正或重定向。历史设计与发布记录保留历史身份。接口说明、局部注释、提交与发布说明分别承担使用契约、实现理由、最终差异与升级动作。

交付前脱离聊天读一遍：下一位能否找到结论、照做或定位修改处；每段是否贡献新事实、解释或行动。重要限制应具体可用，不能靠删掉困难内容制造简短。纯文档任务交付正文；实现疑点先核实，不借写文档更改公开行为。
