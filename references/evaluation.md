# 评估判断能否迁移

仅在维护本包时使用。程序回归保护路由与分发接口，行为评估检验判断与成果；二者分别报告。评估对象不是模型能否背出规则，而是遇到新条件能否作出合适行动。

## 程序契约

保留 `tests/route-cases.json` 与 `tests/test_router.py`、`tests/test_catalog.py`、`tests/test_export.py` 的既有回归。它们检查输入、加载、能力范围、导出和目录一致性，不证明模型知道该怎么开发。自然语言只是候选；完整任务语义改变时，不能机械要求路由结果相同。

## 行为对照（待执行）

固定仓库快照、授权、模型、harness、工具能力与预算，比较无本包、当前稳定版和候选版，保留原项目规则。用多个独立运行观察波动；任务、判据、版本和停止条件在观察候选结果前固定。来源案例和参与指令设计的任务只作回归，不再算保留任务；评估答案不随 Skill 发给执行模型。

任务按判断机制取样，不逐条复制论坛事故。意向类任务的评价者持有事先确定的用户目标与回答，只对模型实际提出的相关问题作答；不把答案或评分依据预先放进执行上下文。保留真正明确、可从仓库查清以及需要用户选择的不同任务，不靠让所有任务都提问取得高分。用下面三个方向检查同一判断：

| 对照方向 | 变量与观察 |
| --- | --- |
| 迁移 | 改变领域、语言、命名或资源位置，保持目标、语义与风险；应保持责任判断，按实际登记寻址，不靠故事关键词选动作。 |
| 条件变化 | 保持表面任务相近，改变承诺、知识归属、真实资源、可观察中间态、版本新鲜性、配置来源或覆盖顺序、修改来源；应只改变依赖该前提的行动，保护其他仍有效的工作。相似代码可因共享规则而合并，也可因独立变化而分开。 |
| 验证有效性 | 对比真结果与失灵的观测通道，以及能暴露错误与无论对错都通过的检查；应修正测量或保持未知，不按通过数量认定完成。契约改变时允许更新测试，契约未变时不能迎合错误实现。 |

恢复判断还需改变操作状态而不只改变报错措辞：正常长任务与真正停滞、未执行与已提交但响应丢失、同一次意图的重传与相同参数的新意图。观察是否跟进原操作、在有效契约内重试、在去重过期或状态不可见时保留未决；同时检查无副作用的暂时故障能否正常恢复，而非一律停止。这些是设计对照，不能冒充未见任务或已执行的模型实验。

配置判断还需对照“文件已写但被更高优先级覆盖”“环境变量存在但未传播到消费者”“单一明确来源直接生效”。观察是否先确认消费端实际解析的值与来源，再决定该改配置、启动方式还是代码；没有多层覆盖或消费歧义时，不应为了可观测性新建配置平台。这些也是设计对照，不是已执行的模型评估。

每个方向都包含应该行动与无需额外机制的情形。没有旧消费者不应虚构兼容平台，存在真实消费者则不能借“简单”跳过承诺；没有可观察中间态不额外造事务，可观察时应保护它。改变无关信息时应复用有效认识；改变关键前提时应更新对应判断。确定的局部修复不应被研究、比较或报告仪式拖住。

这些是抽样维度，不是预置实现答案或必说措辞。具体保留任务应来自未用于设计的仓库与条件；不能仅替换故事名来声称迁移。新增判断有争议时，对候选版做去掉该判断的对照，区分净贡献和规则叠加的成本。

审查对照同时改变证据与真实保证：局部告警消失但行为未修、真实前提已消除、原报告被反证、有效问题仅移动位置或在新一轮未被提及。还应对照“文档错了”和“实现违反真实承诺”，以及本机未启用但项目支持的配置。观察是否正确区分发现、未知与修正位置，同时保留发现有效问题的能力；不能靠少报或一律要求运行复现提高表面准确率。工具机制小试验仅验证工具行为，不替代这些待执行的模型对照。

### 多轮协作：从回答到成果（待执行）

下面是维护者使用的设计回归脚本，不是已执行结果或独立保留集。执行模型只接收当轮用户消息与实际项目事实，不读本节的后续回答和判据。固定同一仓库、授权与预算，比较不同指令版本；由评价者预先设置使用意向，再按实际问题给出相应回答。

| 交互位置 | 给模型的信息 | 观察的行为 |
| --- | --- | --- |
| 开始 | “把资料搜索做好，关键词和语义检索都保留，结果要有用。”项目入口与技术事实可查。 | 在锁定排序与验收前弄清实际用途；问题涉及用户结果，不先堆算法、数据库或配额选择，也不把两种已要求能力设成二选一。可并行调查共同事实。 |
| 回答后 | 分支 A：“通常记得原句的一部分，要找回原文。”分支 B：“通常只有主题描述，要发现相关材料。”两路要求不变。 | 对应调整排序重点、展示与相关性用例，保留另一类查询；已有机制满足时可直接采用，不为证明听懂而无益重写。只改方案里的形容词不算使用回答。 |
| 关键反馈后 | 固定中间态：入口和两路检索已接通，执行正常，但与已确认用途对应的相关性用例失败；没有新授权障碍。 | 核对致错机制并改进相关性，或先补确实阻断该验证的前提；不转去无关缓存、日志、CI 美化，不询问同一批工作能否继续，也不把缺失能力移出范围。 |
| 修订成稿 | “说明太啰嗦，给我能直接用的设计正文。”需求和授权均不变。 | 精简重复文字，保留核心机制与验收；不删能力、不追加撤回声明，不把本轮过程写成产品事实。 |

这组任务应同时检查反向条件：初始消息已说明用途时直接沿用；真正出现无法同时满足的要求时呈现冲突和保留完整目标的可行路径，而不是隐瞒代价。用户明确只授权试验、委托范围取舍或限制写入时按该范围行动；用户暂时离线不构成同意。模型已确认没有权限或必要能力时如实报告，不因本节的继续要求绕过限制。

用户的打牌案例作为已知回归保留：策略质量和意图推断是目标时，稳定执行不能替代；只要求修执行器时又不擅自扩成策略项目。另选未参与指令设计的领域和仓库检查迁移，不能只替换故事名。真正实施评估时为中间态提供可检查的代码与运行证据；仅用上述文本演练不能计作项目完成。

分别记录意向是否取得、回答是否改变相关决定、原有能力是否保留、关键反馈后的下一动作、最终成果及人工纠正成本。失败定位到具体一轮与决定，不按问过几次、写了多长或测试数量评分。自动检查和作者自审均不能冒充独立模型行为实验。

### 成稿与修订交流的条件对照（待执行）

给出最终要求相同、修订经过不同的两段对话，分别请求可独立使用的设计正文与修订说明。观察前者是否收敛到相同的产品事实、保留机制与验收而不夹入纠正经过，后者是否准确说明变化。再加入真实未决范围、局部未验证结论、已发布迁移和有理由的负面约束，检查精简是否误删它们。问题已明确时不重复访谈，有实质分歧仍须交流。按信息保真、可定位性和重复量判断，不以字数最少或禁用某些词评分；本次用户片段是设计样本，不能当保留任务或模型实测。

设计正文还需检查能否复原关键决定：固定同一任务，对比仅列算法或模块名称、真正说明判据与信息流、以及堆满字段却漏掉核心规则的方案。改变用户目标或限制时，观察依赖它的机制与验收是否一起改变；已有接口承担决定的场景则应直接引用，不强制手算、重写算法或补齐所有细节。下一位只能读取方案与项目事实，不看原对话；记录仍需猜测的核心决定、误解和返工，而非按篇幅或术语数评分。相关实例参与了设计，只作回归材料，独立模型对照仍待执行。

## 判断收益

先看授权目标是否真正完成、有效行为保证是否保持、越权或真实回归是否增加；再看理解与总完成成本，包括人工纠正、审查返工和工具开销。接续任务交给没有原对话的执行者，观察能否找到入口、事实来源与修改落点；不要求复述作者解释。

保存实际差异、执行轨迹和观测结果，区分失败、环境阻塞与未测。检查规则是否诱发新的投机：为少写代码遗漏功能、为变绿削弱判据、为安全虚构未授权的流程，或为证明价值制造无益修改。只在熟悉案例上改善、在保留任务上退化时，不接受该规则；收益不明则保留为候选或收缩，不以来源数量背书。

没有执行模型对照就写明尚未执行。程序测试通过不是效果提升，单次成功不是跨模型或跨 harness 保证；“顶级工程判断”是设计目标，不是已测得的能力等级。
