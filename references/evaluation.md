# 评估判断能否迁移

仅在维护本包时使用。路由程序的确定性检查与模型行为的迁移评估分别报告。

## 程序契约

保留 `tests/route-cases.json` 的既有回归和 `tests/test_router.py` 的输入、加载、能力范围、导出及目录一致性检查。它们约束程序行为，不代表模型知道该怎么开发。自然语言只是候选；改变完整任务的语义时，不能机械要求路由结果相同。

## 行为对照（待执行）

固定仓库快照、授权、模型与预算，比较无本包、当前稳定版和候选版。选未参与本轮规则设计的任务；保持原项目规则，不把来源案例或它的简单改名当成全部评估。

| 对照方式 | 应观察的判断 |
| --- | --- |
| 目标、语义和风险相同，换领域、语言与命名 | 修改仍落在承担保证的位置，不依赖题面词语 |
| 任务文字相近，真实依赖或失败代价不同 | 按事实调整兼容与保护，不全有或全无 |
| 同一结构调整，一组保持行为，一组明确改变行为 | 前者保留语义，后者完成授权改变，不机械保守 |
| 相似重复代码，一组共享同一规则，一组只是形式相似 | 合并前者的知识，保留后者的独立变化 |
| 反馈表面相同，一组触达目标，一组只反映观测通道；或新观测推翻局部假设 | 前者据目标结果行动，后者修通道或保留未知；只修订依赖被否定前提的决定 |
| 删除未交付尝试，一组只有聊天理由，一组有真实迁移历史 | 清理前者文字残留，保留后者仍有效的信息 |
| 同一任务，一组相关文件只用于理解，一组文件真正拥有被改变的规则 | 前者可读但不顺手修改，后者在责任处完成必要变化 |
| 同一恢复目标，一组工作区只有本次 Agent 改动，一组混有用户或其他执行者修改 | 前者可撤回本次尝试，后者先区分来源并保护既有工作 |
| 最终内容相同，一组写入过程无人观察，一组被 watcher、并发读者或外部系统观察 | 前者不额外造事务，后者避免暴露无效中间状态 |

以上描述评估维度，不预置每个任务的实现答案。按实际行为及成果判断，不用必须出现某句措辞、加载某个文件或跑更多命令代替能力。

条件对照还应检查认识的有效期：保留证据但改变支撑结论的前提，与只改变无关信息形成对照。前者应更新受影响判断，后者应复用已有工作；用户明确改变目标或权限则依新范围行动。不要通过替换故事名或新增必说措辞来通过评估。

## 取舍

先看授权目标是否完成、真实回归与越权是否增加、下一会话能否继续，再看总完成成本。只在来源案例上进步、在未参与设计的任务上退化时，不接受该规则。无改善或引入重复工作的规则应收缩；保留能改变行动的具体内容，不为字数目标删掉关键边界。

没有执行模型对照就写明尚未执行。程序测试通过不写成效果提升，单次成功不外推全部 harness。
