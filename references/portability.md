# 跨 harness：同一规则，不同接入口

## 安装整个目录

把完整 `invariant-first/` 放入当前宿主实际支持的 Skills 目录，保持内部相对位置。更新旧版时替换这个 Skill 目录，不覆盖项目自己的规则。不要维护两份手工分叉的配置或方法。

核心使用标准 SKILL.md、name/description 元数据与相对资源路径。脚本需要可选的 Python 3.10+ 标准库；规则本身不依赖 Python、shell、网络、浏览器、记忆、子代理或某种 slash command。

## 两种同源安装包

| 分发形态 | 内容 | 使用情况 |
| --- | --- | --- |
| 完整路由包 | 根 SKILL.md + skills/if-*/SKILL.md | 仓库型技能包和可以读取相对文件的编码工具；子技能可独立寻址 |
| single-entry 导出 | 仅根 SKILL.md，子技能转成 GUIDE.md | 只允许一个 Skill 入口的导入器；总入口照样路由到资源文件 |

导出由 `scripts/export_single.py` 从同一来源自动生成，并重写配置、索引和示例路径。不要分别维护两个版本。单入口导出不是把所有指令一次塞进上下文，仍需要宿主能读取引用资源。

完整包有多个 SKILL.md，不保证每个原生上传界面都接受；尤其单 Skill 导入界面应使用 single-entry 包。自动发现、递归扫描和 UI 展示是宿主能力，不由 ZIP 自动提供。

## 四类宿主能力

1. 能发现 Skill 且能读文件：加载根入口，直接读取 PRIMARY；不要求能“调用另一 Skill”。
2. 不识别 Skill 格式但能读文件：用当前宿主的常驻指令引用实际 SKILL.md 路径；这是指令适配，不冒充原生插件。
3. 能读文件但不能运行脚本：读生成的 MASTER-ROUTING，按同一目标与事实选择方法；不为路由器安装工具。
4. 只能接收单段文本：宿主在调用前展开 RULES 与选定主路线、相关专项；也可预装全部方法，但会增加上下文，不能再声称动态按需加载。

没有文件读取能力时，GUIDE.md 版本也不会神奇地被加载。缺编辑或运行能力则交付补丁、正文或判断并标明未执行；缺能力不是新的授权。

## 常驻入口

[AGENTS.snippet](../assets/AGENTS.snippet.md)只是可追加的入口文本。放到宿主实际读取的位置，填正确的安装引用，不覆盖既有要求，也不假定所有工具都读取 AGENTS.md。

`agents/openai.yaml` 是 UI 附加信息；任何工程行为都不依赖它。其它宿主可以忽略，或使用自己的外层适配器；平台专属设置不得进入核心路由配置。
