# 项目知识的去向

只保存下一次工作确实需要且有依据的信息，优先更新项目已有权威位置。

行为保证写进代码、类型或测试；非显然理由留在就地注释或架构说明；用户操作写入用法或运行文档。临时进度仅在确需接续时记录，失效后更新或结束。已有索引就链接这些位置，不复制另一套项目事实。

## 从观察到规则

一次失败先修当前任务。解释它的条件、责任和因果关系，再判断既有方法是否已能处理：能处理就不新增规则；只在当前项目成立就留在项目；确有跨任务价值且获准维护技能包时，更新负责该机制的现有方法。

评估迁移时，换领域与名称应仍能选择正确动作；改变承诺、风险或目标则允许选择不同动作。原案例只是证据，不能因为曾经出错就永久禁止一种机制。已有规则失去条件或收益时收缩、替换或删除。

记录足以定位依据与适用边界即可，不强制经验条目模板，不积累失败目录。旧记录服从当前代码和新观测；不写秘密，不把资料变成操作授权，也不自动修改全局技能。
