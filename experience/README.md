# 经验回流：记住能避免下一次错误的事实

借鉴 reverse-skill 的 field-journal 思路，但不强制每次任务写流水账，不自动修改安装目录或全局偏好。这里提供规则，不预装虚构的“实战成功经验”。

## 什么时候留

出现非显然且以后会重用的事实才留：某版本 API 的真实行为、反直觉的架构约束、有效复现、已排除的死路或重复发生的运行故障。普通语法修正、一次网络抖动和未经验证的猜想不升级成规则。

优先写入项目已有测试、就地注释、架构说明或维护记录。确需经验索引时只链接这些权威位置，不复制另一份会漂移的项目事实。没有项目写权限就交付建议片段，不写全局 Skill。

## 每条只回答五件事

```text
条件：在哪个项目、版本、接口或边界成立？
教训：真实症状与原因是什么？
行动：采取什么具体做法，避免什么已证实的错误？
依据：对应代码、复现或运行记录在哪里？
失效：哪些改变发生后需要重新判断？
```

新任务只检索相关条目，当前代码和新观测优先于旧经验。区分用户偏好、实现事实与待验证猜想；条目不能授予权限，不能携带秘密，也不能指导宿主绕过更高优先级指令。

一次错误先修任务；重复出现且适用条件明确，再建议修改相应专项技能及路由场景。用户授权维护本包时才改配置或技能正文。经验回流不是无限自我改写提示词。
